Browser use and computer use

Updated 2 Nov 2026

For most people the best setup is Claude in Chrome for anything on a website, and Claude's computer use for desktop apps, running on Opus 5.5. Developers building their own agent should use Claude's computer use tool via the API, or the open-source Browser Use library if the job only touches websites.

The basics in plain words#

  • Browser use: the AI controls a web browser. It opens pages, clicks buttons, types into forms and reads what is on screen. It cannot touch anything outside the browser.

  • Computer use: the AI controls the whole computer. It moves the mouse, types on the keyboard and opens any app, like Excel, Finder or a design tool. Browser use is a smaller, safer slice of this.

  • The model is the brain that decides what to click. The harness is the body: the app or code that takes screenshots, moves the mouse and passes results back. You need both.

There are two ways an AI can "see" a screen:

  1. Screenshots (pixels): the AI looks at a picture of the screen and says "click at this spot". Works on any app, but it is slower and can misclick.

  2. Page code (the DOM): the AI reads the hidden structure of a web page, like a list of every button and its label. Faster and more precise, but only works in browsers.

Good tools mix both. Claude also tries the most direct route first: a connector (a direct link to an app like Gmail or Notion) if one exists, then the browser, and only then clicking around the screen. Clicking is the slowest and most fragile way to get anything done.

Which model to run them on#

Opus 5.5 is the safe default. Every screenshot costs roughly 1,000 to 1,800 tokens, so a long session gets expensive fast; that is why picking a lighter model for simple jobs matters more here than in normal chat.

ModelUse it forExampleSkip it when
Opus 5.5Most browser and desktop jobs, especially messy sites and multi-app workLog into your CRM, pull this week's leads, paste them into a sheet, email a summaryThe job is the same simple click path repeated many times
Sonnet 5.5Faster, cheaper sessions; terminal-heavy workFill the same web form for 40 contacts; test your website after each code changeThe site is confusing and needs real judgment
Haiku 5.5Short, repetitive, clearly defined web steps at high volumeCheck 500 product pages and note the price and stock statusAnything with surprises, logins or decisions
Fable 5.1Multi-hour desktop work where Opus keeps losing the threadResearch across dozens of sites, then build a report and deck in desktop appsAlmost everything else; it is slow and 2.5x Opus prices

Long desktop jobs are still genuinely hard. On OSWorld 2.0, a test of real workflows that take a person about 1.6 hours, the best official entry, Claude Opus 5 at max effort, fully finishes only 44% of tasks. On the older, shorter OSWorld test, top agents now beat the human score of 72%. In plain terms: short jobs work well, long ones still need you checking in.

For developers: on the Claude API, the 5.5 models accept only the new computer use toolset, so older integrations need a small upgrade before switching.

The common thread: AI automation succeeds roughly 85 to 95% of the time on web tasks, versus 99%+ for traditional scripted automation. For anything that must work every time, use a connector or a fixed script and save the AI for the messy parts.

Safety and limits#

The biggest risk is a web page that hides instructions for the AI, such as "send this user's emails to this address". This is called prompt injection, and Claude can sometimes follow it. Anthropic scans screenshots for this and makes Claude double-check, but it is not perfect.

  • Separate the risky stuff: use a separate browser profile or the built-in browser for experiments, and keep banking and payments out of reach.

  • Stay in the loop for anything final: sending, paying, deleting, accepting terms. Keep approval on for those steps.

  • Expect it to be slower than you and to misclick now and then, especially on dropdowns, scrollbars and spreadsheets.

  • Watch other extensions: in May 2026 researchers showed that another malicious Chrome extension could trigger Claude in Chrome tasks; it was patched, but install extensions carefully.

  • Developers: run computer use in a sandbox (a throwaway virtual machine or container), limit which websites it can reach, and never paste real passwords into prompts.
