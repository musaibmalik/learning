All five share a 1M token context window, 128K max output, a June 2026 knowledge cutoff, and text plus image input with vision and tool use. Context length does not separate the tiers; price, speed and reasoning depth do.

Fable 5.1: the top tier

Anthropic's most capable model open to all customers, in the Mythos class above Opus. It shares one underlying model with Mythos 5.1 but adds safeguards for biology, cybersecurity and LLM R&D.

Use it when

  • A task runs for hours across many steps and must stay coherent from start to finish.

  • Research has to end in a finished document, spreadsheet or deck, not just notes.

  • You tried Opus 5.5 at xhigh or max effort and it still fell short.

Examples

  • Research every AI training data broker in Europe, compare licensing terms, build a spreadsheet, then write a 20-page report and a deck, in one unattended run.

  • Migrate a large legacy codebase to a new framework where a mistake in hour 1 breaks hour 4.

  • A hard quantitative or scientific problem where Opus keeps getting the logic subtly wrong.

Don't use it when

  • The task is ordinary: an email, a PDF summary, a bug fix, a blog post. You pay 2.5x Opus prices and wait longer for no visible gain.

  • Speed matters. It is the slowest model, so it suits no live chat or real-time UI.

  • Volume is high. Thousands of product descriptions on Fable burns budget.

  • You assume bigger means better on everything. Artificial Analysis scores Fable 5.1 at 53 on its general index, below Opus 5.5 and Sonnet 5.5 at 56. Its edge is long, hard work.

  • The work touches sensitive biology or security topics. Its classifiers may refuse, and you then retry on another model.

API notes: forced tool use returns an error, and editing earlier turns invalidates thinking blocks. Cache reads cost only $0.25 per 1M tokens, so reused long contexts are cheaper than the headline price.

Opus 5.5: the default

Built for long-running agentic coding and knowledge work, with adaptive thinking always on. Anthropic recommends it as the starting point for most workloads.

Use it when

  • You need strong reasoning without Fable's cost.

  • The work is ambiguous and needs sustained judgment; Anthropic says Opus stays clearly ahead of Sonnet here.

  • Accuracy outweighs cost: business plans, legal or financial analysis, strategy, research synthesis.

  • You run multi-hour coding agents, large refactors, vision-heavy workflows or computer use.

Examples

  • Build a full website from a brand system, including components, copy and responsive layout, in one session.

  • Review a business plan for logical holes, weak assumptions and missing financials.

  • Operate a browser or desktop app to finish a multi-step workflow.

  • Read a 300-page contract set and flag conflicting clauses.

Don't use it when

  • The task is simple and repetitive, like classifying 50,000 tickets or extracting invoice fields. Haiku does it for a fraction of the cost.

  • You need instant replies for thousands of users. Use Sonnet or Haiku.

  • Opus has truly hit its ceiling on a long, hard task. That is Fable's job.

Tip: default effort is medium. Raise or lower effort before switching models; Anthropic calls it often the better lever.

Sonnet 5.5: best value

Nearly matches Opus at half the price. It is over 30% faster at generating text than Sonnet 5 and uses fewer tokens for the same work.

Use it when

  • Everyday coding, writing and analysis.

  • You build a product on the API and need good quality at reasonable cost and latency.

  • Terminal and command-line agent work, where it beats Opus on Terminal-Bench.

Examples

  • A Python script that cleans a CSV and charts it.

  • 20 LinkedIn posts in a set brand voice.

  • An n8n or Zapier step that rewrites captions or summarises inbound email.

  • A daily coding assistant in your IDE.

  • Explaining the trends in a dashboard screenshot.

Don't use it when

  • The problem is deeply ambiguous and needs judgment across many steps. Use Opus.

  • You push effort to max to make it work. At high effort its quality and cost converge with Opus, so use Opus.

  • Volume is huge and the task trivial. Haiku is about 20x cheaper on input.

Haiku 5.5: fast and cheap

Built for high-volume, latency-sensitive tasks such as classification, extraction and routing. It is the cheapest model by far, from $0.10 per 1M input tokens.

Use it when

  • You process many items with clear rules.

  • You need near-instant responses.

  • It is one worker in a larger system, taking orders from a bigger model.

Examples

  • Sort 100,000 emails into lead, support, spam or partnership.

  • Pull name, company, price and date from thousands of PDFs into JSON.

  • Route each user message to the right model or tool.

  • Moderate comments on a social page.

  • Live autocomplete or chat suggestions in an app.

  • Subagents that each summarise one webpage while Opus combines the results.

Don't use it when

  • The task needs deep reasoning or nuance: strategy, code architecture, persuasive long-form writing, multi-step research.

  • Errors are expensive. A misread clause or wrong figure costs more than the savings.

  • The task is long and autonomous. It suits short, well-defined jobs.

Mythos 5.1: restricted

The same model and pricing as Fable 5.1, without the extra safeguards. Access is limited to organizations verified through Anthropic programs such as the Cyber Verification Program.

  • Use it when: you are a verified organization doing work Fable's safeguards block, typically defensive cybersecurity such as finding and patching vulnerabilities.

  • Skip it when: you are an individual or a regular business. You cannot get access, and Fable gives identical capability for everything else.

Effort and combining models

These two levers often matter more than which model you pick.

  • Effort level: every current model lets you dial thinking depth up or down. Sonnet on low effort is fast and cheap; Opus on high effort is slower but sharper. Try a different effort before a different model.

  • Combining models: pair a cheap model with a frontier one so most tokens bill at the lower rate. Either an executor escalates hard decisions to an advisor, or an orchestrator delegates bulk work to cheaper workers. Example: Opus plans a research task, ten Haiku subagents each summarise sources, and Opus writes the final report.
