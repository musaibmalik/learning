Agent Harnesses Compared

2026-11-13

A harness is the program wrapped around a model: its loop, tools, memory, permissions and where it runs. On Terminal-Bench the same model scores 9 to 14 points higher in a tuned harness, so picking the harness matters about as much as picking the model. As of November 2026, Claude Code leads on hard multi-file work, Codex wins on cost per task, Cursor owns the editor, and open-source harnesses such as OpenCode and Cline win on model freedom.

At a glance

Harnesses split by where you work with them. The big vendors now ship the same agent in several places: Claude Code runs in the terminal, the IDE and the web, and Codex runs in the terminal, the cloud and on your phone.

The filled chips tie you to one maker's models. The dashed ones let you bring any model, which is the main thing open-source harnesses sell.

Build-your-own SDKs. The Claude Agent SDK is Claude Code as a library (Python, TypeScript): the same tools, loop, hooks, subagents and MCP, billed at API token rates. The OpenAI Agents SDK gives handoffs, guardrails, tracing and sandboxed execution, still at version 0.x. OpenHands, Cline, Cursor and Factory also ship SDKs now.

Benchmarks

The harness moves scores almost as much as the model does. Hand the same model a tuned harness instead of a plain loop and it gains 9 to 14 points on Terminal-Bench 2.0.

The plain runs come from Vals and the tuned ones from Snorkel's board. They are separate runs, so treat the gap as a direction, not a precise number. Among the tuned harnesses the spread is small: GPT-5.5 scores 84.7% in NexAU-AHE, 83.1% in Capy and 82.2% in Codex CLI.

The cleanest harness test holds the model fixed. Composio Bench runs every harness on GPT-6 Astra over 30 stateful tool-use tasks.

This measures tool use across apps, not coding depth, and Composio sells tool integrations, so read it alongside Terminal-Bench. It does show that lean, open harnesses (Cline, Hermes Agent) can beat the vendor ones when the model is the same.

Terminal-Bench moved to version 4.0 on Aug 28 and 4.1 on Nov 9, 2026, and the versions don't compare with each other. On 4.1 the order holds: Claude Code with Opus 65.8%, Claude Code with Sonnet 5.5 63.9%, Codex with GPT-6.1 Sol 60.9% (BenchLM). Claude Code is not only a Claude shell: Kimi K3.1 Pro run inside it scored 60.9% on 4.0, ahead of every Codex entry.

Where sources disagree. AIToolsReview quotes Anthropic's own 4.0 figures (Sonnet 5.5 70.6%, Opus 66.4%), above the board's 61.8% and 64.8%. Morph reports Sonnet 5.5 costing more per task than Opus at max effort, which looks odd but is what the board shows.

What has no score. Cursor, Copilot, Antigravity, OpenCode, Aider, Cline and Hermes Agent have no Terminal-Bench 4.x entry. Cursor's Composer 2 scored 61.7% on the older 2.0 (Firecrawl). No board compares harnesses on SWE-bench; those scores are per model.

Where one beats another. Claude Code beats Codex on hard refactors and extensibility; Codex beats Claude Code on cost, speed and mobile hand-off. Cursor beats both inside an editor. Cline beats Claude Code by 7 points when both run the same model on Composio Bench, so a harness tuned for one vendor is not automatically the best home for another vendor's model.

The benchmark gap between the top harnesses is now smaller than the gap between a tuned harness and a plain one. Choose on workflow, cost and model access first.

Pick this when

Start from where you work and what you need back, then pick. Many teams run two: one deep harness for hard work and one cheap one for volume.

A common pairing in late 2026 is Claude Code for the hard 20% of tasks and Codex for the cheap 80%, with Cursor for anyone who reviews in an editor.
